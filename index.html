Accounts

Chequing, savings, credit cards, cash, investments, loans — each balance updates live from the ledger. For debts (credit cards, loans), enter what you owe as a negative opening balance — e.g. a card with $1,200 owing starts at −$1,200.

How credit cards work here

1. Add the card as an account with Type Credit Card and its current balance owing as a negative opening balance. New purchases on the card are just Expenses on that card account — the amount owing goes up.   2. To pay it, use Pay this card on the card below (or a Transfer in the Ledger): pick the bank account the money comes out of, e.g. Tangerine, and the amount. One entry does both sides at once — Tangerine goes down by that amount and the card owing goes down by the same amount.   3. For a regular payment, set it up once in Recurring as a Transfer — Tangerine → your card — and each Post moves money the same way.

Ledger

Every income, expense, and transfer. Monthly budgets

Set a monthly limit per spending category, and pick which account that spending comes out of — use the “Comes out of” dropdown next to each budget to change it any time. Bars track the current month and turn amber as you approach the limit, red when you pass it. Budgets also feed the Forecast: at each month-end there, whatever is left of the month's budget is taken out of its account to show your balance if you maxed every budget, next to the balance at your current spending — spending already logged counts toward the budget first, so nothing is double-counted.

Recurring transactions

Rent, subscriptions, paycheques — set them up once, then post each one to the ledger with a single tap when it comes due. Use the account dropdown next to each item to change where its money comes out of (or goes into) — Forecast and Between pays follow the account you pick. A Transfer item moves money between two of your accounts: that's how you schedule a credit-card payment — e.g. Tangerine → Visa — so posting it takes the money out of Tangerine and pays the same amount off the card. Skip next misses just the one occurrence shown — nothing is posted to the ledger, and the series carries on from the date after. Delete series is the one that removes them all: every future occurrence goes, and the item disappears from Forecast and Between pays (anything you already posted in the Ledger stays). Deleting a single entry in the Ledger, by contrast, only removes that one entry — it never touches the series here.

Between pays — what's due before your next payday

Pick which recurring income is your pay. For each payday-to-payday stretch below you can now follow the money in plain steps: what's in the account when the period starts → what you'll have once the pay lands → what the bills in between add up to → what's left in the account after those bills are paid. Every bill also shows the balance left right after it comes out, so you can see the account draining bill by bill — not just the final number. Only bills set to come out of the pay account count here — change a bill's account in the Recurring tab and it moves in or out of this walk automatically. A recurring transfer out of the pay account (like a credit-card payment) counts as a bill here too.

No recurring pay found Add your paycheque as a recurring income transaction in the Recurring tab (e.g. “Paycheque”, every 2 weeks), and this view will line your bills up between paydays.

Check a date — which pay period is it in?

Pick any date and this will find the payday-to-payday stretch it falls in (using the same pay you picked in Between pays above), list every bill due in that stretch, and estimate two balances: how much you'll have on that day itself — after that day's bills come out — and how much you'll have left after the whole pay period, once every bill in it is paid. Estimates use your recurring income and bills plus your account balance, the same maths as Between pays, so the “after the period” number here matches the period above.

Cloud Sync — Supabase

Put your data in a real database, separate from this HTML file. Once connected, editing or re-uploading index.html on GitHub / Netlify will not lose your data — it loads from Supabase. It also syncs the same profile between phone and PC. Your browser copy stays as an offline cache.

✓ Baked-in connection is active — this file points at your database

This copy of index.html already has your Supabase URL + publishable key baked in, so any browser that opens it connects automatically — no pasting the key on your phone or work PC, and no Save connection step. Auto-sync is on by default, and the home screen you see on open lets you pull your cloud copy in one tap.

How it works

1
Create a free Supabase project

Go to supabase.com → New project. Pick any name (e.g. finance-tracker) and a region near you. Wait ~1 minute for it to provision. Free tier is enough.

2
Create the table — run this SQL once

In Supabase: left sidebar → SQL Editor → New query → paste the SQL below → Run. You only do this once.

3
Already done — the link is baked into this file

Your Project URL and publishable key are already set as BAKED_SUPABASE_URL / BAKED_SUPABASE_KEY at the top of this file's script, so any browser opening it is already connected and auto-syncs — nothing to paste on your phone or work PC, ever. The Connection form below is only a per-browser override / fallback. If the values ever change, edit only those two lines — never find-and-replace placeholder words across the whole file.

4
Nothing to do on your other devices

Just open the same site there — the home screen asks whether to start new or pull from the cloud, so pick Pull there. Auto-sync is on by default and pushes a few seconds after every change. The Push / Pull buttons below are there if you ever want to sync manually.

SQL to run in Supabase

create table if not exists public.finance_tracker_data ( id text primary key, profile_name text, data jsonb not null, updated_at timestamptz not null default now() ); alter table public.finance_tracker_data enable row level security; drop policy if exists "pft anon select" on public.finance_tracker_data; drop policy if exists "pft anon insert" on public.finance_tracker_data; drop policy if exists "pft anon update" on public.finance_tracker_data; drop policy if exists "pft anon delete" on public.finance_tracker_data; create policy "pft anon select" on public.finance_tracker_data for select using (true); create policy "pft anon insert" on public.finance_tracker_data for insert with check (true); create policy "pft anon update" on public.finance_tracker_data for update using (true) with check (true); create policy "pft anon delete" on public.finance_tracker_data for delete using (true);
Open Supabase dashboard →

Security note: these policies let anyone with your anon / publishable key read/write this one table. That's fine for the non-sensitive setup you described (amounts, categories, profile names — no bank logins, account numbers, or passwords). Don't put sensitive info in payee names if you share the key. Never bake in or share the secret / service_role key. If you baked the publishable key into this file, keep the Git repo and Netlify site private.

What syncs, what doesn't

Each local profile syncs as one row in finance_tracker_data, keyed by its profile ID, with the full JSON (accounts, transactions, budgets, recurring, categories) in the data column. If the same profile exists in the cloud with a newer updated_at, Pull will show you the cloud date before overwriting. Push always overwrites the cloud copy with what's on screen. If you use two different profile names on two devices, they'll be two separate rows — use List profiles in cloud to pull a profile created elsewhere onto this device.

Backup & download

Your entries auto-save in this browser under your current profile. If you've connected Supabase in the Cloud Sync tab, they also save to your database — that's the copy that survives editing the HTML and syncs between devices. Export a JSON backup regularly as an extra safety net.

Your data — My Finances

The JSON backup contains everything for the current profile — accounts, transactions, budgets, recurring items, and categories. The CSV is a spreadsheet-friendly copy of the ledger. Importing a backup replaces what's in the current profile and auto-saves over it. To keep profiles separate on another device, export each profile before you switch.

Hosting it yourself

  1. GitHub: create a repository, add the downloaded file as index.html, then enable GitHub Pages (Settings → Pages → deploy from the main branch) to get a public URL.
  2. Netlify: drag the folder containing index.html onto Netlify's Sites page — it deploys instantly. You can host as many separate sites as you like on the free plan, so this and your geo tool can live side by side, each with its own URL.
  3. Editing at work: edit the file in the GitHub web editor or push changes from any machine; the host redeploys automatically. With Supabase connected, your data lives in the database — redeploying the HTML won't lose it. Without Supabase, each browser keeps its own copy, so use export/import to move books between devices.
